## 1. 文档目的

定义 Project Sonata 中**角色与乐器**的设计：分类、职能、体系、技能卡系统、入队顺序、教学曲线。

战斗机制（共鸣规则、ToneStack、伤害公式、资源系统等）归 [BattleDesign.md](./BattleDesign.md)；本文档聚焦于"**谁来执行这些机制**"——每类乐器的玩法身份、风格、与共鸣系统的对应关系、剧情与机制的耦合、配队与 build 多样性。

## 2. 设计哲学

### 2.1 核心原则

| 原则 | 含义 |
|---|---|
| **每类乐器 = 一种战斗思考方式** | 弦乐想"铺"，管乐想"补"，鼓组想"控 + 拐"，Polyphonic 想"改写" |
| **不允许全能一拖二** | 每类乐器有明确短板，强制玩家配队互补 |
| **乐器之间互补，不重叠** | 弦乐的群体铺音 ≠ 管乐的单体爆发，即使数值相近体验也不同 |
| **体系需要核心角色** | 每套玩法体系都有 1-2 个核心角色作为锚点，但避免单一角色绑定整个体系 |
| **机制随角色逐步解锁** | 主线三人组覆盖核心循环；支线角色每个引入一个新机制 |
| **乐器身份与剧情身份一致** | 大提琴"低音失声"叙事 = 防御型低速高收益机制 |

### 2.2 五类乐器的玩法身份

```
鼓组（Drum Kit）
  ── "我不挂音，但我决定节奏、保人、引爆——我是通用拐"
弦乐（Strings）
  ── "我把音符撒出去，让所有敌人都沾上颜色"
管乐（Winds）
  ── "我看准时机，一击致命地补完旋律"
Polyphonic（多声部）
  ── "我同时管理多个声部，能改写规则"
主角（Protagonist）
  ── "我记录发生过的事，让它再发生一次"（TODO）
```

### 2.3 设计参考

- **原神角色定位**：主 C / 副 C / 辅助 / 治疗 的功能划分
- **星穹铁道配队模板**：单 C 双拐一生存 / 双 C 一拐一生存
- **传统 JRPG 职业系统**：互补 + 体系化分工
- **乐队编制**：节奏组（鼓+贝斯）/ 旋律组（弦+管）/ 和声组（键盘+拨弦）的实际分工

## 3. 乐器大类总览

### 3.1 五大类

| 大类 | 中文名 | 设计核心 | 是否参与挂音 | Phase 1 状态 |
|---|---|---|---|---|
| **Drum Kit** | 鼓组 | 通用拐（Tempo + 生存 + DoT 引爆 + 节拍点生成） | ❌ 不挂音 | ✅ Phase 1 必做（鼓） |
| **Strings** | 弦乐 | 群体铺音 + 多段攻击 | ✅ 主要挂音方 | ✅ Phase 1 必做（小提琴） |
| **Winds** | 管乐 | 精准补音 + 单体爆发 | ✅ 关键补音方 | ✅ Phase 1 必做（长笛） |
| **Polyphonic** | 多声部 | 调性切换 + 和弦补全 + 体系联动 | ✅ 多音齐挂 | 🚧 Phase 2（钢琴、竖琴） |
| **Protagonist** | 主角 | 记录 / 复播（元机制） | ❓ 未定 | 🚧 Phase 3（废弃车站强化） |

### 3.2 分类依据

**鼓组独立成类**的关键判据：**是否参与音高系统**。
- 鼓组不挂音、不参与和弦构成，专精节奏维度（Tempo / 行动条 / 节拍点）
- 有音高的打击乐（马林巴、木琴）归入 Polyphonic，因为它们能同时发出多个明确音高

**Polyphonic** 涵盖所有"能同时发多声部"的乐器：
- 钢琴（键盘中和声乐器）
- 竖琴（拨弦中和声乐器）
- 马林巴 / 木琴（有音高的打击和声乐器）
- 手风琴、管风琴（如有）

## 4. 鼓组（Drum Kit）

### 4.1 设计核心

**"我不挂音，但我决定节奏、保人、引爆——我是通用拐"**

鼓组是唯一**不参与 ToneStack** 的乐器大类。它的价值分布在四个维度，是 Project Sonata 的"通用第三人选"——任何配队都欢迎一个鼓组。

### 4.2 鼓组的四个职责

| 职责 | 描述 | 触发方式 |
|---|---|---|
| **Tempo 操控** | 调整己方/敌方行动条 | 主动技能 |
| **生存（盾奶）** | 给己方护盾、治疗、净化 | 主动技能 + 被动卡 |
| **DoT 引爆** | 提前结算敌人身上的 DoT | 主动技能（双流派，见 4.4） |
| **节拍点生成** | 比其他角色多产生节拍点 | 被动 / 基础技能自带 |

### 4.3 战斗定位

| 维度 | 表现 |
|---|---|
| 数值倾向 | HP 中高（站得住才能稳定控场），ATK 低 |
| 挂音能力 | ❌ 完全无 |
| 单体伤害 | 低 |
| 群体伤害 | 低 |
| 生存能力 | 中高（自身能扛，能保人） |

### 4.4 双流派引爆手设计

**核心设计**：鼓组的 DoT 引爆能力通过**技能卡 build** 切换两种流派，而不是绑定到固定角色。

| 流派 | 节奏 | 伤害曲线 | 核心技能卡 | 适用场景 |
|---|---|---|---|---|
| **挂 DoT 流派** | 看怪 Speed（被动） | 平滑、无视己方行动条 | 强化小三和弦、延长 DoT 持续 | 对速度慢的 Boss、杂兵战 |
| **引爆流派** | 看鼓手 Speed（主动） | 集中、伤害有亏损 | 引爆结算卡（亏损 20%-30%） | 速杀、节奏控制、爆发窗口 |

**关键约束**：
- 引爆伤害亏损 **20%-30%**：每层 DoT 引爆结算 70%-80% 的剩余伤害。让玩家觉得"亏损但值得"
- 鼓组不能两种流派同时最强——技能卡槽位有限，必须取舍
- 混合 build（少量引爆 + 大量 DoT 叠层）可能反而是最优解

**参考**：星穹铁道卡芙卡（引爆型 DoT 主 C）的反面教材——我们的设计中，"引爆 vs 不引爆"是 build 选择，不是角色绑定，避免了卡芙卡困境（后续 DoT 角色设计必须迁就她）。

### 4.5 鼓组与共鸣系统的关系

- 鼓组**不挂音、不参与 ToneStack 构成**
- 鼓组的力量在 ActionTimeline（§9）+ 资源系统（§8）+ DoT 系统（待实现）
- 鼓组的"重拍"机制：消耗敌人身上的 Harmonic Armor（见 BattleDesign §7），触发额外共鸣伤害

> TODO 鼓组的"共鸣增幅"机制——是直接增加伤害倍率？还是触发额外共鸣链？还是允许"重新触发上次共鸣"？
> TODO 鼓组是否需要至少一个挂音技能（避免完全无法独立应对某些场景）

### 4.6 已有 / 计划乐器

| 乐器 | 入队方式 | 定位差异 |
|---|---|---|
| 鼓（Drum） | 主线必得（花园） | 通用型：Tempo + 节拍点 + 引爆 |

> TODO 是否需要多种鼓组乐器（如定音鼓 / 电子鼓 / 世界打击乐）作为后续扩展

### 4.7 短板

- 完全无法独立凑和弦，必须配队
- 对"沉默的鼓"型敌人（见剧情大纲 §6.6）有特殊劣势
- 在直伤体系中战略价值低于在 DoT / 烧血体系（直伤队需要的是更直接的"伤害放大"）

## 5. 弦乐（Strings）

### 5.1 设计核心

**"我把音符撒出去，让所有敌人都沾上颜色。"**

弦乐是**铺音主力**，负责建立 ToneStack 的初始状态。特征是**多段、群体、可持续**。

### 5.2 战斗定位

| 维度 | 表现 |
|---|---|
| 主要任务 | 群体铺音、维持 ToneStack、多段输出 |
| 数值倾向 | HP 中、ATK 中、SPD 中高（出手频繁） |
| 挂音能力 | ✅ 强（群体 + 多段） |
| 单体伤害 | 中 |
| 群体伤害 | 高 |
| 生存能力 | 中 |

### 5.3 弦乐与共鸣系统的关系

- 弦乐**铺底**，让多个敌人身上都有 ToneStack
- 弦乐玩家关心的是"如何同时管理多个敌人的 stack 状态"
- 弦乐**不擅长**精准补音（单次伤害分散到多目标，难以打出最后一击）

**机制特征**：
- 多段攻击：一次技能可能给同一目标挂多个音，或给多个目标各挂一个音
- 持续输出：DPS 平稳但缺乏爆发
- 中性搭配：跟所有其他大类都能配合

### 5.4 已有 / 计划乐器

| 乐器 | 入队方式 | 定位差异 |
|---|---|---|
| **小提琴（Violin）** | 主线必得（花园） | 高速群体铺音、广撒网 |
| **大提琴（Cello）** | 黑森林支线 | 低速、防御型、护盾 + 低音铺底（C/D 为主） |
| 中提琴（Viola） | > TODO | > TODO 是否需要 |
| 低音提琴 | > TODO | > TODO 是否需要 |

### 5.5 短板

- 单体爆发不足，难以独立击杀 Boss
- 铺音"广而不精"，需要管乐配合才能凑出关键和弦
- 对"快速清音"型敌人脆弱（铺的音被立即清除）

## 6. 管乐（Winds）

### 6.1 设计核心

**"我看准时机，一击致命地补完旋律。"**

管乐是**单体爆发 + 精准补音**的专家。特征是**高 ATK、高 SPD、低 HP**——典型的玻璃大炮。

### 6.2 战斗定位

| 维度 | 表现 |
|---|---|
| 主要任务 | 单体爆发、精准补音、击杀关键目标 |
| 数值倾向 | HP 低中、ATK 高、SPD 高 |
| 挂音能力 | ✅ 精准（单目标单音，但伤害高） |
| 单体伤害 | 极高 |
| 群体伤害 | 低 |
| 生存能力 | 低（需要被保护） |

### 6.3 管乐与共鸣系统的关系

- 管乐**完成和弦的最后一击**，是 CG→E / CE→G 路径的"第三音专家"
- 管乐玩家关心的是"什么时候出手、补哪个音"
- 管乐跟弦乐是**天作之合**：弦乐铺音 + 管乐收尾

**机制特征**：
- 单体高倍率：每个音都附带可观伤害
- 改写能力（部分管乐如双簧管）：能移除 / 替换敌人身上的音
- 路径选择权：管乐的高爆发让它适合走 TriadViaFifth 路径（CG→E 大倍率）

### 6.4 已有 / 计划乐器

| 乐器 | 入队方式 | 定位差异 |
|---|---|---|
| **长笛（Flute）** | 主线必得（花园） | 标准单体爆发、C/E/G 主力 |
| **双簧管（Oboe）** | 黑森林支线 | 改写型：能替换敌人身上的某个音；可走烧血流（自伤换改写） |
| 单簧管（Clarinet） | > TODO | > TODO 是否需要 |
| 巴松管（Bassoon） | > TODO | > TODO 低音管乐 |

### 6.5 短板

- HP 低，被反噬型共鸣（如 Dissonance 自伤）惩罚严重
- 群体处理能力差，应对群怪吃力
- 出手选择压力大——选错音直接浪费高伤害机会

## 7. Polyphonic（多声部乐器）

### 7.1 设计核心

**"我同时管理多个声部，能改写规则。"**

Polyphonic 是**机制吃食能手**——数值偏低，但拥有独占机制（调性切换、多音齐挂、补全任意音）。是游戏中最"策略型"的大类。

### 7.2 战斗定位

| 维度 | 表现 |
|---|---|
| 主要任务 | 调性切换、多声部操作、应急补全、体系联动 |
| 数值倾向 | HP 中、ATK 中低、SPD 低（行动慢但影响大） |
| 挂音能力 | ✅ 多音齐挂（独占） |
| 单体伤害 | 中低 |
| 群体伤害 | 中 |
| 生存能力 | 中 |

### 7.3 Polyphonic 与共鸣系统的关系

- Polyphonic **改写战场规则**，而不只是参与
- 独占机制：
  - **多音齐挂**：一次技能给同一目标挂多个音（独占的"快速凑和弦"能力）
  - **调性切换**：改变当前战斗的全局调性（影响所有共鸣效果）
  - **补全任意音**：根据 stack 现状，自动补全最缺的那个音
- Polyphonic 玩家关心的是"全局策略"而非局部最优

### 7.4 已有 / 计划乐器

| 乐器 | 入队方式 | 定位差异 |
|---|---|---|
| **钢琴（Piano）** | 尖塔支线 | 黑白键双形态：白键治愈增益 + 黑键攻击改写；调性切换；可走烧血流（黑键自伤） |
| **竖琴（Harp）** | 尖塔支线 | 完全五度专家；治疗 + 净化 + 护盾；可与鼓组配合走 DoT/烧血 |
| 马林巴（Marimba） | > TODO | > TODO 是否需要 |
| 木琴（Xylophone） | > TODO | > TODO 是否需要 |
| 手风琴（Accordion） | > TODO | > TODO 是否需要 |

### 7.5 钢琴的双形态设计（草案）

| 形态 | 风格 | 机制倾向 | 流派倾向 |
|---|---|---|---|
| **白键（White Key）** | 温和、大调、治愈 | 治疗、增益、护盾、净化 | 直伤队生存位 / DoT 队净化位 |
| **黑键（Black Key）** | 锋利、半音阶、攻击 | 攻击、改写敌人音符、强化伤害；自伤换效果 | 烧血流 C / 改写型拐 |

> TODO 是否允许"灰键"（同回合同时使用黑白键）的高级技巧

### 7.6 Polyphonic 联动（详见 §10.5）

多个 Polyphonic 同队时触发"和声共鸣 buff"——但**单走也必须可用**，联动是奖励不是门槛。

### 7.7 短板

- 数值偏低，单纯算 DPS 不划算
- 速度慢，出手频率低
- 操作复杂度高，新手难以驾驭
- 与鼓组协同需注意（都偏慢，可能导致队伍整体节奏过缓）

## 9. 乐器与共鸣系统的对应关系

### 9.1 各大类"擅长"的共鸣

| 大类 | 擅长共鸣 | 理由 |
|---|---|---|
| Drum Kit | 全部（触发者）+ DoT 引爆 | 不挂音，但能强化任何已形成的共鸣；引爆 DoT 是独占维度 |
| Strings | Major Triad（铺音凑成） | 群体挂音，容易在多敌人身上同时形成大三和弦 |
| Winds | Dissonance（反向利用） + Major Triad（精准补全） | 高爆发让反噬代价可控；单体精准补音擅长凑大三和弦 |
| Polyphonic | Perfect Fifth + Minor Triad | 竖琴是五度专家；钢琴的多声部适合处理小三和弦色彩 |
| Protagonist | > TODO | > TODO |

### 9.2 推荐路径偏好

| 大类 | TriadViaThird（CE→G） | TriadViaFifth（CG→E） |
|---|---|---|
| Strings | ✅ 默认路径（铺 C-E 让管乐收 G） | ⚠️ 不擅长（弦乐铺 C-G 容易被误触发 Perfect Fifth） |
| Winds | ⚠️ 中性（可走但非首选） | ✅ 首选路径（高爆发配合高倍率） |
| Polyphonic | ✅ 擅长（多音齐挂，路径自选） | ✅ 擅长（竖琴就是五度专家） |
| Drum Kit | - | - |

## 10. 体系设计

### 10.1 四套体系总览

Project Sonata 的配队设计围绕**四套玩法体系**展开。体系之间允许混编（详见 §10.6），不是硬隔离。

| 体系 | 核心共鸣 | 节奏 | 关键角色 | 配队模板 |
|---|---|---|---|---|
| **直伤** | Major Triad | 单回合爆发 | 弦乐（铺音）+ 管乐（收尾） | 弦 + 管 + 鼓（拐） |
| **DoT** | Minor Triad | 多回合累积 + 引爆 | 弦乐（铺音）+ 鼓组（引爆） | 弦 + 管/鼓 + 鼓/竖琴 |
| **烧血** | Dissonance | 自伤 → 爆发 | 双簧管 / 钢琴黑键（自伤型） | 烧血 C + 生存 + 鼓 |
| **Polyphonic 联动** | 多种共鸣 | 慢节奏、机制连锁 | 多个 Polyphonic 同队 | 2-3 个 Polyphonic |

### 10.2 直伤体系

**核心思路**：通过 Major Triad（40 基础伤害，路径加成后更高）单回合高爆发。

**配队模板**：
```
小提琴（Strings 铺音）+ 长笛（Winds 收尾）+ 鼓（Drum Kit 拐 / Tempo）
```

**关键机制**：
- 弦乐铺 C-E，管乐收 G（走 TriadViaThird 路径）
- 或弦乐铺 C-G，管乐收 E（走 TriadViaFifth 高倍率路径）
- 鼓组提供节拍点 + Tempo 操控

**参考**：原神蒸发/融化单 C 队（胡桃行秋钟离）、星铁毁灭 C（刃/饮月）

### 10.3 DoT 体系

**核心思路**：通过 Minor Triad（25 基础伤害 + DoT）持续掉血，由引爆手选择何时结算。

**配队模板**：
```
铺音位 + DoT 叠层位 + 鼓组（双流派引爆手）
```

**关键机制**：
- Minor Triad 触发后给目标附加 DoT（5/回合 × 3 回合，> TODO 数值待定）
- 鼓组在 build 时选"挂 DoT 流派"或"引爆流派"
- 引爆流派：每层 DoT 引爆结算 70%-80% 的剩余伤害

**参考**：星铁卡芙卡（反面教材：绑死整个体系）、黑天鹅（DoT 层数化改进版）

**避开卡芙卡陷阱的关键**：
- 引爆 vs 不引爆是**鼓组 build 选择**，不是另一个角色
- 鼓组在两种 build 下都可用，玩家不强制选其一
- 未来引入"Polyphonic 引爆型"角色也不冲突，只是另一种引爆方式

### 10.4 烧血体系

**核心思路**：通过 Dissonance（15 真伤 + 5 反噬）的高伤害特性，配合"自伤转化收益"机制打出爆发。

**配队模板**：
```
烧血 C（双簧管 / 钢琴黑键）+ 生存位（鼓组 / 竖琴）+ 拐
```

**关键机制**：
- 反噬积累 → 转化为下次共鸣伤害加成
- 反噬到阈值 → 触发"狂暴"状态
- 反噬可以被治疗位"吃掉"（治疗位吸收反噬转化成护盾）

**两种烧血路径**（参考星铁镜流+刃）：
- **镜流式（分散自残）**：消耗队友 HP 转自身攻击 buff（生存压力分散）
- **刃式（自身叠层）**：自伤叠层 → 释放高伤（单兵作战）

**参考**：
- 原神胡桃（E 扣血换攻击）
- 杀戮尖塔红石卡组（受伤加伤）
- 星铁镜流（消耗队友 HP）+ 刃（自伤叠层）

### 10.5 Polyphonic 联动体系

**核心思路**：多个 Polyphonic 同队时触发"和声共鸣 buff"，通过机制连锁打出战术。

**配队模板**：
```
钢琴 + 竖琴 + 第三个 Polyphonic（或非 Polyphonic 拐）
```

**联动 buff 草案**：

| 同队 Polyphonic 数量 | 联动效果 |
|---|---|
| 1 | 无（单走模式） |
| 2 | 调性切换 CD 减少 / 共鸣伤害 +10% |
| 3 | 共鸣伤害 +30% / 解锁"和声终曲"团队大招 |

**单走定位**：每个 Polyphonic 都能进其他队伍当拐（竖琴当治疗，钢琴当调性切换工具人），数值偏低但机制独特。

**参考**：原神双岩双火共鸣、星铁追击队（真理医生 + 托帕）

**关键约束**：
- 联动是**奖励**而非**门槛**——单 Polyphonic 也必须可用
- 避免强制 3 Polyphonic 才能玩（否则队伍槽位太死，3 格队伍下完全没法配队）

### 10.6 体系之间的混编

**核心原则**：体系之间必须能混编，不允许硬隔离。

**典型混编场景**：

| 混编 | 思路 |
|---|---|
| 直伤 + DoT | 弦乐同时铺大三和小三和弦，玩家在战斗中动态选择 |
| 直伤 + 烧血 | 双簧管平时走直伤，关键时刻改写时自伤触发烧血 |
| DoT + 烧血 | Dissonance 反噬 + Minor DoT 双层掉血 |
| Polyphonic + 任意 | 任何配队都可以塞一个 Polyphonic 当拐 |

**实现关键**：
- 乐器大类的"体系归属"应该软，不硬绑定
- 弦乐可同时铺音给直伤和 DoT
- 管乐可走直伤也可走烧血（双簧管）
- 鼓组是真正的"通用拐"，能进所有体系
- Polyphonic 自带体系（联动）+ 通用控制位

## 11. 队伍配置

### 11.1 队伍规模

**3 格队伍**。

- 战斗中我方最多 **3 名角色**同时出场
- 敌方最多 **5 名目标**（参考星铁）
- 主角参战时占用 1/3 队伍槽，代价较高（所以"主角非必须出战"是合理设计）
- 配队模板参考：**单 C 双拐** / **双 C 一拐** / **三 Polyphonic 联动** 等

**3 格的好处**：
- 决策聚焦，每个角色戏份重
- 配队压力小（"3 个都能派上用场"）
- 与现有工程一致（场景已预留 3 个 PlayerSlot）
- 技能卡系统提供的 build 多样性弥补了体系密度问题

**3 格的代价**：
- 体系密度受限，必须靠技能卡补足
- 鼓组作为"通用第三人选"地位更稳（这同时是优点也是设计约束）

### 11.2 互补关系

```
Strings ⇄ Winds      弦乐铺音 ↔ 管乐收尾
Drum Kit → All        鼓组增幅所有人（拐 + 生存 + 引爆）
Polyphonic ⇄ All      Polyphonic 改写战场规则
Protagonist → All     主角（TODO）元机制
```

### 11.3 反互补关系（设计约束）

| 组合 | 推荐度 | 理由 |
|---|---|---|
| 两个鼓组 | ❌ 不推荐 | Tempo 操控会互相覆盖，节拍点生成过剩 |
| 三个 Polyphonic | ⚠️ 推荐/特殊 | 联动极强但节奏过缓；3 格队伍下完全锁死 |
| 纯管乐队（3 管乐） | ❌ 不推荐 | 铺音能力严重不足 |
| 纯弦乐队（3 弦乐） | ⚠️ 中性 | 缺乏爆发，Boss 战吃力 |
| 双 Polyphonic + 1 | ✅ 推荐 | 联动 buff + 槽位灵活 |

> TODO 是否在系统层面禁止某些组合，还是让玩家自行承担后果

### 11.4 主角出战规则

- 默认**不出战**
- 占用 3 格队伍槽中的 1 格（如果出战）
- 特殊剧情战斗强制出战（如废弃车站终局之战）

## 13. 技能卡系统

### 13.1 设计目标

**角色固定，技能可塑。**

- 一个乐器 = 一个角色（永久存在，不可替换）
- 角色的具体玩法由**装备的技能卡**决定
- 同一角色通过不同卡组可以进入不同体系（详见 §10）

**核心约束**：没有卡 = 没有技能。获得角色时自动获得几张基础技能卡。

### 13.2 卡的装备机制

| 维度 | 规则 |
|---|---|
| **槽位数** | 每角色 **4 个技能卡槽** |
| **必须装满** | 出战前必须装备 4 张卡，否则不能出战 |
| **卡的归属** | 每张卡绑定到固定角色（不可跨角色使用） |
| **卡的持久性** | 永久解锁（收集后永远有），可在不同战斗前换装 |
| **战斗中换装** | ❌ 不允许（战斗中卡组锁定） |

**4 槽意味着**：
- 一个角色的"build"由 4 张卡组合决定
- 同一角色可以有多套 build（如鼓组的"挂 DoT build"vs"引爆 build"）
- 玩家在战斗前选最优组合

### 13.3 卡的类型

| 类型 | 描述 | 占用槽位 | 节拍点消耗 |
|---|---|---|---|
| **主动技能卡** | 主动施放的技能（如挂音、攻击、治疗） | 1 槽 | 通常是消耗（-1 ~ -2） |
| **被动 buff 卡** | 装备即生效的被动效果（如 ATK +10%） | 1 槽 | 不消耗 |
| **生成卡** | 产生节拍点的"普攻型"卡（如鼓组基础技能） | 1 槽 | 通常是回复（+1 ~ +2） |
| **大招卡** | 消耗共鸣槽的终极技能，**每角色最多 1 张** | 1 槽 | 不消耗节拍点（消耗共鸣槽） |

**大招卡的特殊规则**：
- 每角色的 4 槽中，**最多装 1 张大招卡**
- 大招不消耗节拍点，消耗共鸣槽（满槽才能释放，见 BattleDesign §8.1）
- 不装大招卡也能出战（4 槽全装主动/被动），但失去大招能力

### 13.4 卡的稀有度

| 稀有度 | 来源 | 强度 |
|---|---|---|
| **基础卡** | 角色获得时自动获得（3-5 张） | 入门级，定义角色核心机制 |
| **进阶卡** | 剧情 / 探索 / 商店 / 战斗奖励 | 改变机制（如双流派引爆卡、形态切换卡） |
| **大师卡** | Boss 战 / 隐藏支线 | 显著强化或解锁高级 build |

> TODO 卡的总数规划（每角色几张？总数？）
> TODO 卡是否可升级（基础 → 进阶）？还是固定等级？

### 13.5 卡与资源系统的关系

详见 [BattleDesign.md §8 资源系统](./BattleDesign.md#8-资源系统)。

- 主动技能卡消耗**节拍点**（全队共享）
- 生成卡产生节拍点
- 大招卡消耗**共鸣槽**（角色独立）
- 被动 buff 卡不消耗任何资源

**节拍点典型数值**：

| 卡类型 | 节拍点消耗 | 备注 |
|---|---|---|
| 基础普攻 / 生成卡 | +1 | 普通节奏 |
| 标准技能 | -1 | 大多数主动技能 |
| 强力技能 | -2 | 高伤害 / 多目标 / 强控制 |
| 鼓组生成卡 | +2 或 +3 | 鼓组独占的强节拍点生成 |
| 大招 | 0（消耗共鸣槽） | 不占节拍点 |

### 13.6 平衡约束

| 约束 | 理由 |
|---|---|
| 同一技能卡不能装两份 | 避免叠加 exploit |
| 卡组之间应有"互斥"设计 | 避免全装最强卡的"最优解" |
| 4 槽必须有 1 张生成型卡（推荐） | 否则节拍点枯竭，无法持续战斗 |
| 大招卡最多 1 张 | 见 §13.3 |
| 装备的卡之间不能完全冲突 | 如"挂 DoT 卡" + "引爆卡"共存可能导致 DoT 还没叠满就被引爆 |

### 13.7 前人参考对照

| 参考 | 借鉴点 | 与本项目差异 |
|---|---|---|
| **空洞骑士护符** | 装备制、slot 限制、可换装 | 我们是角色专属，护符是通用 |
| **Hades 武器变异** | 每局重选、技能替换 | 我们是永久解锁，不是每局重选 |
| **原神命之座** | 角色专属、改变技能机制 | 命之座是永久被动，我们是装备选择 |
| **FF7 重制 武器系统** | 武器 = 技能组，换武器换 build | 我们用"卡"代替"武器"作为容器 |
| **杀戮尖塔卡组** | 卡组组合决定玩法 | 我们是实时战斗而非卡牌战斗 |

**最接近的设计**：Hades 武器变异 + 原神命之座 + 空洞骑士护符的混合体。

## 15. 设计决策日志

最新决策放最上面。

### 2026-07-19 · 技能卡系统：4 槽 + 永久解锁 + 必装满

**决定**：每角色 4 个技能卡槽，必须装满才能出战；卡永久解锁；战斗中不能换装；大招卡每角色最多 1 张。

**理由**：
- 4 槽对应 4 个机制维度（主动 / 被动 / 生成 / 大招），保持 build 多样性
- 永久解锁 + 战前换装：玩家可针对不同战斗优化 build，但战斗中决策不混乱
- 大招卡最多 1 张：避免大招链 exploit，同时让玩家选择"要不要带大招"成为 build 决策
- 必须装满：避免"少装一张换 buff"的边缘 exploit

### 2026-07-19 · 队伍 3 格 + 主角可选

**决定**：战斗中我方最多 3 名角色同时出场；主角默认不出战；主角出战时占用 1/3 队伍槽。

**理由**：
- 决策聚焦、角色戏份重，适合单机叙事驱动
- 技能卡系统提供的 build 多样性弥补了 3 格的体系密度损失
- 现有工程已预留 3 个 PlayerSlot，无需重构
- 主角占 1/3 代价高，所以"主角非必须出战"是合理设计

### 2026-07-19 · 双流派引爆手（避开卡芙卡陷阱）

**决定**：鼓组的 DoT 引爆能力通过技能卡 build 切换"挂 DoT 流派"和"引爆流派"，不绑定到固定角色。

**理由**：
- 避免卡芙卡困境——后续 DoT 角色设计不必围绕"是否兼容引爆手"展开
- 让"引爆 vs 不引爆"成为玩家 build 选择，而非角色身份绑定
- 引爆伤害亏损 20%-30% 让两种流派都可行

### 2026-07-19 · 四套玩法体系

**决定**：项目围绕四套玩法体系设计——直伤（Major Triad）/ DoT（Minor Triad + 引爆）/ 烧血（Dissonance 反噬）/ Polyphonic 联动。体系之间允许混编。

**理由**：
- 每套体系对应不同的玩家思考方式，提供多样化体验
- 乐器大类与体系的关系是"软归属"，配队自由度高
- 体系混编避免"直伤队就是直伤队"的硬隔离
- Polyphonic 联动作为"体系之外的体系"，给多 Polyphonic 配队一个目标

### 2026-07-19 · "鼓组"独立成类，不与有音高打击乐合并

**决定**：鼓组（Drum Kit）作为独立大类，专门对应 Tempo / 行动条 / 节拍点维度；有音高的打击乐（马林巴、木琴）归入 Polyphonic。

**理由**：
- 鼓组**不参与音高系统**，跟 ToneStack 完全解耦，机制独立性高
- "是否产生明确音高"是天然的分类边界
- "鼓组"比"打击乐"更口语化、更亲切，符合项目调性
- 让鼓组专精 Tempo + 节拍点 + 生存 + 引爆，是"通用拐"的天然候选

### 2026-07-19 · 钢琴和竖琴合并为 Polyphonic 类

**决定**：钢琴、竖琴、未来可能的马林巴 / 木琴统一归入 Polyphonic 大类。

**理由**：
- 共同特征：能同时发出多个明确音高（多声部）
- 共同定位：全能位 / 特殊机制改写者
- 共同入队节点：湖中尖塔支线
- "Polyphonic" 覆盖范围广，未来扩展乐器不需要新建大类

### 2026-07-19 · 角色设计独立成文

**决定**：单开 `Docs/CharacterDesign.md`，不放在 `BattleDesign.md` 里。

**理由**：
- 角色设计涉及机制 / 叙事 / 美术三层，关注点与战斗规则不同
- 角色会随剧情演化反复改，跟相对稳定的战斗规则分离更易维护
- 单独文档方便后续加入美术参考、配音、剧情对话等内容

### 2026-07-19 · 主角参战问题留白（部分决定）

**决定**：主角参战时占 1/3 队伍槽；默认非必须出战；具体战斗机制待其他系统稳定后再定。

**理由**：
- 主角的"记录 / 复播"机制依赖其他系统的成熟度（共鸣系统、ActionTimeline、资源系统）
- 过早决定会限制其他大类的设计空间
- 留白不阻塞 Phase 1 / Phase 2 开发（主角强化是终章前才需要的）
